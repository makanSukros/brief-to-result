# Launch Kit

**ID:** `launch-kit`

**Outcome:** A coherent set of launch drafts built from the same approved product facts.

Use when a user requests a Launch Kit or a multi-channel product launch bundle. For a single announcement, use O09 instead. Apply the [shared pack contract](../references/outcome-packs.md).

## Inputs

Required: product/change description and enough source material to distinguish real capabilities from plans. Use audience, availability, CTA, channel limits, and an optional explicitly selected profile when provided. Do not require a launch date or price if the copy can be truthful without them.

## Method

1. Lock supported facts and material qualifiers: who can access the feature, platform limits, rollout status, pricing changes, and the actual next action. Separate shipped features from plans.
2. Use I04 to identify the most concrete benefit for this audience. State benefits as plausible use cases, not measured results unless evidence exists.
3. Use M06, C09, and O09 to adapt the message. Write for each channel instead of repeating one paragraph with different lengths.
4. Use I09 to create a launch checklist with actual dependencies. Missing owners or dates are open assignments, not invented commitments.
5. Compare every draft against the shared ledger. Recheck prices, dates, limits, feature names, URLs, and CTA destinations. Repair contradictions before delivering.

## Default output contract

| Deliverable | Required content |
| --- | --- |
| `message` | One positioning sentence, headline, and three supported benefits; fewer benefits when the evidence supports fewer |
| `email` | Subject, preview text, body, and supported CTA |
| `social-posts` | Three meaningfully different short drafts; follow requested channels and counts instead of assuming platform limits |
| `faq` | Up to five likely questions, answered only from supplied or verified information |
| `launch-checklist` | Pre-launch, launch, and follow-through checks; include availability and support readiness |
| `evidence-and-open-items` | Source references, missing or disputed facts, and any deliverable blocked by them |

If a CTA destination is absent, use only an action justified by the brief or mark that component blocked. Do not invent a link. Unanswered FAQ questions belong in open items, not in fictional answers. An evidence-backed message with fewer claims is better than a full quota of invented benefits.

## Example invocation

```text
Use Brief to Result: Launch Kit.
Use the attached release notes and the Northstar profile I selected.
Write one email and two LinkedIn posts for existing customers.
Do not mention pricing or a launch date. Prepare drafts only.
```

**Done means:** requested drafts are present, factual qualifiers agree across channels, limits have been checked where measurable, and blocked items are explicit. It does not mean anything has been published.
