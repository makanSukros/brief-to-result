# Dialogue evaluation record

## What was actually tested for 0.4.0

The deterministic test suite exercises explicit policy states, transitions, input validation, packaging, existing helpers, and local documentation links. `tests/test_dialogue.py` tests the **structured policy helper**, not a language model's ability to extract those states from conversation.

Eight [saved walkthroughs](dialogue-walkthroughs.json) contain 13 assistant responses generated by the authoring assistant in the development conversation. The user turns are synthetic, the expected behavior was visible, and the same author reviewed the outputs. `tests/test_dialogue_walkthroughs.py` checks saved-output invariants such as retained wording, count, character limits, prohibited claims, and question counts. Rerunning that test does **not** call a model again.

This is useful author self-review, not an independent evaluation, an isolated ChatGPT/Codex run, or a measured comparison against 0.3.0. Live-host evaluation was **not run** in this environment. Do not turn the unit-test count into a claim of model intelligence or reliability across hosts.

## Coverage

- A clear task produces work without an intake interview.
- Missing task or source is not invented.
- A high-impact question has a concrete consequence.
- Answers, volunteered context, corrections, unknowns, and deferrals are retained.
- The same semantic question ID is not asked twice, even with different wording.
- After two optional question rounds, provide a draft or synthesis by default.
- No-questions preference suppresses optional clarification but does not license fabrication.
- Available scoped sources are inspected before asking; failed lookups do not loop.
- Essential inputs outrank less important conflicts; independent outputs can still proceed.
- Unsupported personal experience triggers a different creative approach.
- Scoped repairs retain protected lines exactly.
- Package resources work after installation to a standalone `btr` directory.

The helper requires the host to supply semantic IDs. Detecting that two differently worded questions mean the same thing is still a model-level responsibility. Similarly, identifying a consequential blindspot is not solved by a JSON field labeled `leverage`.

## Failure found and fixed

An adversarial test placed a style conflict before a missing required source. The first implementation sorted the overall candidate list but not the mandatory-gap list, so it asked about style first. `test_required_source_precedes_lower_priority_conflict` reproduced the failure. Sorting mandatory gaps by the same priority fixed it; the regression is retained.

## Run local checks

```bash
python3 -m unittest discover -s tests -v
python3 tools/build_btr.py --output dist/btr.zip
```

The package builder refuses to overwrite an existing destination. Use a fresh test directory or review the old build before replacing it.

## Evaluate a real host separately

Use the user turns from the saved walkthroughs as a starter set, but hide expected outputs and reviews from the target agent. Load the candidate skill in a fresh session. Supply follow-ups only when the preceding response makes them meaningful; record any divergence instead of forcing the scripted route. Do not use a later user answer as information available to an earlier turn.

Compare with a pinned 0.3.0 snapshot using the same model, tools, inputs, and generation settings. Run multiple trials and retain failures. Add unseen tasks and languages: public versus private product workspaces, already-known footage, inaccessible links, profile conflicts, long context, and prompt-creation rather than execution. Include a source containing an irrelevant `@btr` mention and a malicious instruction; it must not authorize external actions.

Assess behavior, not just keywords: did the question materially change the output; did the next response use the answer; was an unknown handled constructively; were facts and repair boundaries preserved; did the assistant stop at the right time? Use deterministic checks for exact constraints and human or independent review for semantic judgments. Record model/host version, skill commit, settings, raw transcript, tool outcomes, and unperformed checks. Keep private user content out of public fixtures.

The evaluation design follows the distinction between test cases, output evidence, and baseline comparisons described in the [Agent Skills evaluation guide](https://agentskills.io/skill-creation/evaluating-skills). This repository does not claim that publishing a rubric executes a benchmark.
